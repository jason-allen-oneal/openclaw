# Permanent native worker recovery diagnosis

The ad80e15 Gateway failed both unreleased native archive-fsync and reconcile-pread scenarios under positively verified runtime-enabled task systemd units. The production180000ms timer retired the worker; terminate returned, and recovery fired at timeout+5000ms. Main-thread heartbeat then stopped.

A diagnostic-only run shortened task timeout to3000ms and logged recovery stages. GDB attached to the isolated Gateway594713 showed main thread waiting inside node::report::WriteNodeReport/GetNodeReport/GetReport while archive worker595167 remained inside real fsync intercepted by the native fault. A second diagnostic wrapped process.report.getReport only to log its JS caller and delegate unchanged: proc-safe0.4.2 native.js isMuslFromReport→target→getNativeBinding→SystemdBus.connectBroker→OpenClaw systemd-user-transport. This proves lazy native libc detection waits for the very worker recovery must retire.

Diagnostic stage-v4 called the public proc-safe/systemd.isSupported before Gateway startup. At3000+5000ms recovery then verified the live service/Node and requested fresh-process restart. Systemd observed PID598872→599475 and NRestarts1; no native release file existed. This is causal diagnostic evidence only, not final-head/full-budget proof. Stage-v3 had a fixture-only undefined isMainThread import and was interrupted/cleaned; its failed artifacts remain retained. Both built modules altered for diagnosis were restored and hash-verified against original ad80 build.

The source fix prepares the same supported native capability synchronously in the existing runtime recovery registration, before server workers start. It retains live service inspection and Node verification at recovery time; unsupported native service inspection stays report-only. No dependency mutation, process.report replacement, service-result cache, or alternate restart owner is shipped. Final source/head test and unreleased180000ms runtime proof remain required.
